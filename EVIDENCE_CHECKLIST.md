# Recruiter portfolio: evidence and release checklist

## Before merging
- Confirm precise FIS job title, start/end dates and 2–3 responsibilities. Add only approved, non-confidential examples.
- Confirm MSc completion date and exact dissertation title.
- Confirm current country preferences and country-specific work-authorisation wording.
- Supply an up-to-date, role-targeted CV; add a working Download CV link once the file is committed.
- Validate email and LinkedIn ownership and check external links signed out.
- Verify GitHub Pages source settings and root URL after merge.

## Case studies to complete
1. RegPulse / financial systems: problem, implemented scope, requirements-to-controls example, screenshot, repository or sanitised walkthrough, tests and limitations. Label prototypes accurately.
2. AutoTime AI: exact personal contribution, architecture, integration flow, demo, failure handling and human review. Date and scope any verified test results. Do not imply launch readiness, customers or time savings without evidence.
3. MSc loan default: dataset provenance/licence, methods, baseline, train/test split, leakage checks, class balance, evaluation metrics, reproducibility and limitations.

For each case study use: problem → contribution → implementation → measured result → evidence.
Replace self-rated skill percentages with linked SQL queries, Python code, tests and outputs.
No invented numbers. Report benchmark and user outcomes separately.

## Role targeting
- Analyst/application CV: lead with FIS, then financial systems evidence, then automation.
- Automation CV: lead with AutoTime implementation and reliability evidence, then FIS and data work.
- Keep stated titles as target roles; do not represent them as prior employment titles.

## Repository maintenance
The static root index.html is the canonical proposed portfolio.
The old nested template entry point uses the same replacement content to avoid conflicting recruiter messaging.
No external libraries, tracking, forms or build step are required.
Existing template assets and licences remain in place; the replacement page is newly authored.
